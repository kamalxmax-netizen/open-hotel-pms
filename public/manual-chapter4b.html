1. Early Check-out (Early C/O)
แขกต้องการออกก่อนวันที่จองไว้
สถานการณ์

แขก In-house โทรมาบอกจะออกวันนี้ ทั้งที่จองถึงอีก 2–3 คืน ระบบจะเรียก Shorten Flow อัตโนมัติ เพื่อคำนวณว่าต้องเก็บค่าปรับ (Shorten Fee) หรือไม่ และมีเงินคืนเท่าไหร่

หลักการคิดราคา
📌 กฎทอง: คิดค่าห้องเฉพาะคืนที่แขก พักจริง เท่านั้น
  • พักคืนเดียว → คิดแค่คืนนั้น
  • พัก 2 คืนจาก 4 คืนที่จอง → คิด 2 คืน
  • ถ้า Pre-paid เกิน → คืนเงินส่วนต่าง (หักค่าปรับก่อน ถ้ามี)
สูตรคำนวณ Shorten Fee
ยอดที่จ่ายมาแล้ว (Prepaid Net)บาท A
ค่าห้องที่พักจริง (New Total)บาท B
ส่วนเกิน (Overpaid = A − B)บาท C
ค่าปรับสูงสุด (Fee Cap)บาท D
เงินคืนแขก = C − ค่าปรับที่เก็บจริงบาท
⚠️ ค่าปรับ (Shorten Fee) เก็บได้ไม่เกิน Fee Cap ที่ระบบแสดง — ห้ามเก็บเกินนั้น
ขั้นตอนการทำ Early C/O
เปิด Reservation ของแขก → แก้ไขวันเช็คเอาท์
ไปที่ Reservations → ค้นหาชื่อแขก → คลิก Edit → เปลี่ยน Checkout Date เป็นวันที่แขกจะออกจริง
ตัวอย่าง: จองถึง 25 มี.ค. แต่จะออก 23 มี.ค. → เปลี่ยนเป็น 23 มี.ค.
ระบบดึง Settlement Preview อัตโนมัติ
หลังจากบันทึกวันออกใหม่ ระบบจะเรียก API /settlement-preview?action=shorten และแสดง Shorten Fee Modal พร้อมตัวเลขครบถ้วน
ตรวจสอบตัวเลขใน Shorten Fee Modal
ระบบแสดง: Prepaid Net / Old Total / New Total / Overpaid / Fee Cap — ตรวจสอบให้ถูกต้อง
เลือกนโยบายค่าปรับ
ตัวเลือก A: เก็บค่าปรับ — ใส่จำนวนเงินค่าปรับ (ไม่เกิน Fee Cap) และเลือกวิธีรับ (Cash / Transfer / Card)
ตัวเลือก B: ยกเว้น (Waive) — ติ๊ก "No fee — Waive shorten stay penalty" ถ้าผู้จัดการอนุมัติ
เงินคืนที่แขกได้ = Overpaid − ค่าปรับ (แสดงใต้ modal อัตโนมัติ)
เลือกวิธีคืนเงิน (Refund Method)
เลือก Cash / Transfer / Card แล้วกด Confirm Shorten
ดำเนินการ Check-out ตามปกติ
หลัง Shorten สำเร็จ → Check-out ตามขั้นตอนปกติ → คืนกุญแจ → อัปเดตสถานะห้อง HK
Flow สรุป
แขกแจ้งออกก่อน
→
แก้ไข Checkout Date
→
Shorten Fee Modal
→
เก็บ/ยกเว้น Fee
→
Check-out สำเร็จ
กรณีตัวอย่าง
กรณี A — Prepaid
จ่ายล่วงหน้า 3 คืน แต่ออกหลัง 1 คืน
Prepaid = 3,000 บาท | New Total = 1,000 บาท
Overpaid = 2,000 บาท | Fee Cap = 500 บาท
เก็บค่าปรับ 500 บาท → คืนแขก 1,500 บาท
กรณี B — Waive
VIP Guest ขอออกก่อน — ผู้จัดการยกเว้นค่าปรับ
Overpaid = 2,000 บาท | Fee Cap = 500 บาท
ติ๊ก "No fee — Waive"
ค่าปรับ 0 บาท → คืนแขกเต็ม 2,000 บาท
🖥️ ลองดูหน้า Reservations — ค้นหาจอง In-house แล้วกด Edit

2. Very Late Arrival (แขกมาดึกมาก)
แขกมาหลังเที่ยงคืน หรือใกล้รุ่งสาง
แบ่งเป็น 2 กลุ่มหลัก
กลุ่ม A — จองมาล่วงหน้า (Pre-booked)
มีการ์ดจอง / OTA / Phone booking
ระบบมีข้อมูลอยู่แล้ว — เช็คอินตามปกติ
ถ้ามี Pre-payment → ตรวจยอดใน Billing Panel ก่อน
ถ้ายังไม่ได้ชำระ → เก็บเงินตอนเช็คอิน
⚠️ วันเช็คเอาท์ยึดตามที่จอง ไม่ใช่นับจากเวลาเช็คอินจริง
กลุ่ม B — Walk-in (ไม่ได้จอง)
มาถึงแผนกหน้าเลยตอนดึก
ทำเหมือน Walk-in ปกติ (ดูหมวด 2)
⚠️ วัน Check-out คือ 12:00 น. ของวันเดียวกัน (Business Date ปัจจุบัน)
เช่น Walk-in ตี 2 คืน 22 มี.ค. → Check-out 12:00 น. 23 มี.ค.
เรื่อง Business Date ที่ต้องระวัง
Business Date ≠ Calendar Date เสมอไป
ระบบ PMS จะรันช่วง Night Audit เพื่อเปลี่ยน Business Date เป็นวันถัดไป
ถ้า Night Audit ยังไม่รัน → Business Date ยังเป็นเมื่อวาน
ถ้า Night Audit รันแล้ว → Business Date เป็นวันนี้แล้ว

ผลที่เห็น: Arrivals List จะแสดงการจองตาม Business Date ที่ active — ตรวจสอบ Business Date ที่มุมบนขวาของระบบก่อนเสมอ
ขั้นตอนสำหรับแขก Pre-booked มาดึก
ค้นหาการจองในระบบ
Reservations → ค้นหาชื่อ / Booking Code — ตรวจสอบสถานะเป็น "Active" และวันเช็คอินตรงกัน
ตรวจสอบ Pre-payment
เปิด Billing Panel — ดูว่ามียอดชำระมาแล้วหรือไม่ ถ้ายังค้างอยู่ → เก็บก่อนให้ห้องพัก
กด Check-in ตามปกติ
ดูขั้นตอนใน หมวด 2 (Check-in) — ไม่มีความแตกต่างจากการเช็คอินทั่วไป
แจ้งแขกเรื่องวัน Check-out
ย้ำเสมอว่าต้องออกก่อน 12:00 น. ตามวันที่จอง — การมาดึกไม่ได้ขยายเวลาเช็คเอาท์
ถ้าแขกต้องการขยายเวลา → แจ้งไปที่ LCO (Late Check-out) มี fee เพิ่มเติม
ขั้นตอนสำหรับ Walk-in มาดึก
สร้าง Reservation ใหม่
New Reservation → เลือก Source = Walk-in → วัน Check-in = Business Date ปัจจุบัน → Check-out = วันถัดไป 12:00 น. (= 1 คืน)
ตรวจสอบห้องว่างที่เหมาะสม
เช็ค Room Board ก่อนเลือกห้อง — ห้องที่กำลังจะ Check-out วันนี้อาจยังไม่พร้อม
เก็บเงิน / เปิดใบเสร็จ
เก็บค่าห้อง 1 คืนตาม Rate ปัจจุบัน → Check-in → แจ้งแขกว่าต้องออก 12:00 น. วันนี้
🚨
ข้อควรระวัง: อย่าตั้ง Check-out หลัง 12:00 น. ของวันถัดไปสำหรับ Walk-in ดึก เพราะระบบจะคิดเป็น 2 คืน ทั้งที่แขกพักไม่ครบ
🔄
3. Room Move & Plan Room Move
ย้ายห้องทันที หรือวางแผนล่วงหน้า — 3 แบบราคา
ภาพรวม: 2 โหมดหลัก
โหมด A
Move Now (ย้ายทันที)
ย้ายห้องวันนี้เลย เหมาะสำหรับกรณีแขกร้องเรียนเรื่องห้อง หรืออัปเกรดตอนนี้
โหมด B
Plan Move (วางแผนล่วงหน้า)
กำหนดวันเริ่มและวันสิ้นสุดของการย้าย ระบบจะย้ายอัตโนมัติเมื่อถึงวันนั้น เหมาะสำหรับแขกที่พักยาวและต้องการเปลี่ยนห้องบางช่วง
3 นโยบายราคา (Pricing Policy) — สำคัญมาก
แบบที่ 1: Keep RTC (ราคาเดิม / Complimentary Upgrade)
ใช้เมื่อ: อัปเกรดฟรี / ย้ายเพราะห้องมีปัญหา ไม่คิดเงินเพิ่ม
ราคาต่อคืนของแขกไม่เปลี่ยน — จ่ายเท่าเดิมทุกอย่าง
แบบที่ 2: Rate Grid (คิดราคาใหม่ตาม Rate Grid)
ใช้เมื่อ: แขกขอย้ายไปห้องที่แพงกว่า โดยจ่าย Top-up ตามราคาตลาด
ระบบดึงราคาจาก Availability Grid → แสดงส่วนต่าง (Diff) ให้เห็นก่อนยืนยัน
ตัวอย่าง: ห้องเดิม 1,000 บาท/คืน → ห้องใหม่ตาม Grid = 1,400 บาท/คืน → แขกจ่ายเพิ่ม 400 บาท/คืน
แบบที่ 3: Rate Grid + Discount (คิดราคาใหม่ + ส่วนลด)
ใช้เมื่อ: ย้ายไปห้องแพงกว่า แต่ให้ส่วนลดพิเศษ
เลือกประเภทส่วนลด: เปอร์เซ็นต์ (%) หรือ จำนวนเงิน (Fixed)
ต้องใส่เหตุผลส่วนลด (Discount Reason)
ตัวอย่าง: Grid = 1,400 บาท/คืน → ลด 10% → แขกจ่าย 1,260 บาท/คืน
ขั้นตอนการทำ Room Move (Move Now)
เปิด Reservation แขก → กด "Room Move"
ใน Reservation Detail Page → ปุ่ม Room Move / Change Room → เปิด Room Move Modal
ตรวจสอบ Assigned Room Lock (ถ้ามี)
ถ้าห้องมี Lock สีเหลือง (Do Not Move) → ต้องใส่หมายเหตุ Override ก่อนดำเนินการต่อ
Lock นี้ป้องกันการย้ายแขกโดยไม่ตั้งใจ — ให้ระบุเหตุผลให้ชัดเจน
เลือก Room Type ปลายทาง
ระบบแสดง Rate Grid อัตโนมัติ → ดูส่วนต่างราคา (Current vs New) ก่อนตัดสินใจ
เลือกห้องที่ต้องการ
ระบบดึงรายการห้องว่างใน Room Type ที่เลือกให้อัตโนมัติ
เลือก Pricing Policy
▸ Keep RTC = ราคาเดิม (ฟรี หรือย้ายเพราะห้องมีปัญหา)
▸ Rate Grid = คิดตลาด (แขกขอเอง จ่าย Top-up)
▸ Rate Grid + Discount = คิดตลาดพร้อมส่วนลด (ใส่ % หรือจำนวนเงิน + เหตุผล)
ใส่เหตุผลการย้าย (Move Reason)
บังคับใส่ — เช่น "Guest request upgrade" / "AC malfunction" / "Maintenance issue"
กด Confirm Move
ระบบบันทึก Room Move History และอัปเดตห้องในระบบ → แจ้ง HK ทำความสะอาดห้องเก่า
ขั้นตอน Plan Room Move (วางแผนล่วงหน้า)
Room Move Modal → แท็บ "Plan Move"
เลือกแท็บ Plan Move (ด้านบนของ Modal)
กำหนด Start Date และ End Date
Start Date: วันที่แขกจะย้ายเข้าห้องใหม่ (ต้องเป็นวันถัดจาก Check-in หรือหลังจากนั้น)
End Date: วันที่กลับมาใช้ห้องเดิม หรือ Check-out
ตัวอย่าง: แขกพัก 1–10 มี.ค. ต้องการห้องดีกว่า 5–8 มี.ค. → Plan 5–8 มี.ค.
เลือก Room Type / ห้อง / Pricing Policy
เหมือนกับ Move Now — ระบบดึง Rate Grid ตาม Plan Start/End Date
เลือก Do Not Move (ถ้าต้องการล็อค)
ติ๊ก "Do Not Move" + ใส่หมายเหตุ เพื่อป้องกันให้ระบบไม่สามารถย้ายห้องออกไปโดยไม่ตั้งใจ
บันทึก Planned Move
กด Save → ระบบสร้าง Planned Move Entry → แสดงในรายการ Planned Moves ด้านล่าง Modal
ตัวอย่างการใส่ราคาทั้ง 3 แบบ
สถานการณ์ Pricing Policy วิธีใส่ราคา ผลลัพธ์
แอร์เสีย — ย้ายให้ฟรี Keep RTC ไม่ต้องใส่อะไร — ใช้ราคาเดิม ราคาไม่เปลี่ยน
แขกขอห้องดีขึ้น Rate Grid ระบบดึง Rate ใหม่อัตโนมัติ แสดงส่วนต่าง แขกจ่าย Top-up ส่วนต่าง
Upgrade พร้อมลด 10% Grid + Discount เลือก % → ใส่ 10 → ใส่เหตุผล Rate Grid × 0.90
Upgrade ลด 200 บาท/คืน Grid + Discount เลือก Fixed → ใส่ 200 → ใส่เหตุผล Rate Grid − 200 บาท/คืน
💡
เคล็ดลับ: ระบบแสดงตัวเลขสรุปก่อนยืนยันเสมอ — ตรวจสอบ "Current Total" vs "New Total" ให้แน่ใจก่อนกด Confirm
🖥️ ลองดู Room Board — เห็นห้องว่างและสถานะ
📅
4. Extend Stay — OTA & Walk-in
แขกต้องการพักต่อ — กฎราคาต่างกันตามแหล่งที่มา
กฎทองเรื่องราคา Extend Stay
📌 จำให้ขึ้นใจ:
  • OTA → ราคา Extend ยึดตาม OTA rate เดิม (ไม่เปลี่ยน)
  • Walk-in → ราคา Extend ยึดตาม Rate Grid (ราคาตลาดวันนั้น)
  • ราคา OTA > Walk-in เสมอในระบบ — ถ้า OTA ต่อ แขกจ่าย OTA rate ต่อไป
4 สถานการณ์ Extend Stay ที่พบบ่อย
สถานการณ์ A: OTA — อยู่ห้องเดิมต่อ (Same Room)
แขก OTA ต้องการอยู่ต่อในห้องเดิม และห้องยังว่างอยู่

วิธีทำ:
  1. เปิด Reservation → กด "OTA Extend Stay" หรือ "Extend"
  2. Modal "OTA Extend Stay Orchestrator" เปิดขึ้น
  3. เลือก Strategy = Same Room
  4. ตั้งวัน Checkout ใหม่
  5. ระบบ Preview → ถ้าไม่มี Blocker → กด Commit Extension Plan
✅ ราคาส่วน Extension ใช้ Rate Grid — ไม่ใช่ OTA rate (เพราะ Extension เป็น Walk-in segment)
สถานการณ์ B: OTA — ห้องเดิมถูกจองโดยคนอื่น (Blocker)
แขก OTA ต้องการอยู่ต่อ แต่ห้องเดิมมีการจองคนอื่นเข้ามา

ระบบจะแสดง Blocking Item — ต้องเลือกว่าจะทำอย่างไรกับ Blocker

ทางเลือก:
  • Swap Blocker: ระบบจะหา Swap Candidate — เลือกห้องอื่นสำหรับ Blocker แล้วขยาย OTA ต่อ
  • เปลี่ยน Strategy เป็น Different Room: ย้ายแขก OTA ไปห้องอื่นแทน (สร้าง Linked Booking)
สถานการณ์ C: OTA — ย้ายไป Room Type อื่น (Linked Booking)
แขก OTA ต้องการต่อ แต่ขอย้ายไป Room Type ที่ต่างออกไป

วิธีทำ:
  1. กด OTA Extend Stay → เลือก Strategy = Different Room
  2. เลือก Move Mode: Move Now (ย้ายทันที) หรือ Plan Move (กำหนดวัน)
  3. เลือก Target Room Type + Target Room
  4. ถ้า "Move Now" ก่อน Checkout OTA — จะมีตัวเลือก:
    • Option A: Keep OTA as-is — ย้ายทันที เก็บวัน OTA ไว้เดิม
    • Option B: Shorten OTA first — ย่อ OTA ก่อน แล้วสร้าง Walk-in segment ต่อ
  5. กด Commit → ระบบสร้าง Linked Booking (OTA + Walk-in ใหม่)
⚠️ หลัง Commit → FO ต้องอัปเดตวันใน OTA Platform เอง ระบบไม่ได้อัปโดยอัตโนมัติ
สถานการณ์ D: Walk-in — ต่อพักเพิ่ม (Extend)
แขก Walk-in ในบ้านต้องการอยู่ต่อ

วิธีทำ:
  1. เปิด Reservation → เปลี่ยน Checkout Date เป็นวันใหม่ → บันทึก
  2. ระบบคำนวณราคาตาม Rate Grid ของวันที่ขยายออกไป
  3. เพิ่มยอดในบิล → เก็บเงินเพิ่ม หรือ Post to Room
💡 ถ้าห้องว่าง → ขยายง่ายมาก แค่เปลี่ยนวันออก ถ้าห้องไม่ว่าง → ต้องทำ Room Move ก่อน
ตารางสรุป: Extend Stay ทำแบบไหน?
กรณี Source Room Type ราคาที่ใช้ ระบบสร้างอะไร
ต่อห้องเดิม, ห้องว่าง OTA เดิม Rate Grid (Extension = WI segment) Linked Stay (OTA+WI)
ต่อห้องเดิม, ห้องว่าง Walk-in เดิม Rate Grid ขยาย Checkout ปกติ
ย้ายไป Type เดิม, Swap ได้ OTA เดิม Rate Grid Swap + Linked Stay
ย้ายไป Type ใหม่ OTA ใหม่ Rate Grid ของ Type ใหม่ Linked Booking ใหม่

Checklist สรุปก่อนทำ Special Operations
ตรวจสอบก่อนดำเนินการทุกครั้ง
Early C/O
  • ตรวจสอบ Prepaid Net และ Fee Cap ก่อนเสมอ
  • ได้รับอนุมัติก่อน Waive ค่าปรับ
  • ยืนยันวิธีคืนเงินกับแขก
  • Check-out ปกติหลัง Confirm Shorten
Late Arrival
  • เช็ค Business Date ก่อนเสมอ
  • Pre-booked: ตรวจ Pre-payment ใน Billing Panel
  • Walk-in: แจ้งแขกว่า Check-out = 12:00 วันนี้
  • อย่า set Check-out ข้ามวันโดยไม่ตั้งใจ
Room Move
  • เลือก Pricing Policy ให้ถูกก่อน Confirm
  • ตรวจ Diff ราคาก่อนยืนยัน
  • Plan Move: ตรวจวันให้ถูกต้อง
  • แจ้ง HK ทำความสะอาดห้องเก่า
Extend Stay
  • OTA: ใช้ Rate Grid สำหรับส่วน Extension
  • Walk-in: ขยาย Checkout และเพิ่มยอดในบิล
  • ตรวจ Blocker ก่อน Commit เสมอ
  • OTA + Room Move: อัปเดต OTA Platform ด้วยตัวเอง

5. คำศัพท์ที่ต้องรู้ (Glossary)
ศัพท์เทคนิคและคำย่อที่ใช้ในหมวดนี้
Early C/O (Early Check-out)
การเช็คเอาท์ก่อนวันที่กำหนดไว้ในการจอง
Shorten Flow
กระบวนการในระบบเมื่อแขกขอออกก่อนกำหนด — คำนวณค่าห้องจริง + ค่าปรับ + เงินคืน
Shorten Fee Modal
หน้าต่างป๊อปอัพที่ระบบแสดงเพื่อยืนยันการ Early C/O พร้อมตัวเลขครบ
Prepaid Net
ยอดเงินที่แขกชำระมาแล้วสุทธิ (หักค่าธรรมเนียมธนาคาร/OTA แล้ว)
Fee Cap
ค่าปรับสูงสุดที่เรียกเก็บได้ตามนโยบายโรงแรม — ห้ามเก็บเกิน
Waive
ยกเว้น / ยกโทษ — ในที่นี้คือยกเว้นค่าปรับ Early C/O โดยไม่เก็บ
Overpaid
ยอดที่แขกจ่ายเกินกว่าค่าห้องจริง = Prepaid − New Total
Refund
การคืนเงินให้แขก — ต้องเลือกวิธีคืน: Cash / Transfer / Card
Business Date
วันที่ธุรกิจของระบบ — อาจไม่ตรงกับปฏิทินจริงถ้า Night Audit ยังไม่รัน
Night Audit
กระบวนการปิดวัน — รันแล้ว Business Date เปลี่ยนเป็นวันถัดไป
Pre-payment / Pre-paid
เงินที่แขกหรือ OTA ชำระมาล่วงหน้าก่อนเช็คอิน
Very Late Arrival
แขกมาเช็คอินหลังเที่ยงคืน หรือใกล้รุ่งสาง
Room Move
การย้ายห้องพักของแขกที่อยู่ในบ้านแล้ว ไปยังห้องอื่น
Plan Room Move
การวางแผนย้ายห้องล่วงหน้า กำหนดวันเริ่ม-สิ้นสุด
Move Now
โหมดย้ายห้องทันที มีผลตั้งแต่วันนี้
Pricing Policy
นโยบายราคาที่ใช้เมื่อย้ายห้อง: Keep RTC / Rate Grid / Rate Grid + Discount
Keep RTC
คงราคาห้องเดิมไว้ ไม่เปลี่ยนแปลง (RTC = Room Type Change)
Rate Grid
ตารางราคาห้องตามประเภทห้องและวันที่ — ราคาตลาดมาตรฐานของโรงแรม
Top-up
ส่วนต่างที่แขกต้องจ่ายเพิ่มเมื่อย้ายไปห้องที่แพงกว่า
Discount Type
ประเภทส่วนลด: Percent (%) หรือ Fixed (จำนวนเงินคงที่)
Discount Reason
เหตุผลที่ให้ส่วนลด — บังคับกรอกเมื่อใช้ Rate Grid + Discount
Assigned Room Lock
การล็อคห้องที่ assign ไว้ เพื่อป้องกันการย้ายโดยไม่ตั้งใจ
Do Not Move
สถานะที่ป้องกันไม่ให้ระบบย้ายห้องออก — ต้อง override ด้วยหมายเหตุ
Extend Stay
การขยายวัน Check-out ออกไป — แขกต้องการพักต่อ
OTA (Online Travel Agency)
แหล่งจองออนไลน์ เช่น Booking.com, Agoda, Expedia
OTA Rate
ราคาที่ OTA กำหนดมาในการจอง — ใช้ตลอดช่วงที่จอง ไม่เปลี่ยน
Walk-in Rate
ราคาที่คำนวณจาก Rate Grid สำหรับแขก Walk-in หรือส่วน Extension
Linked Booking / Linked Stay
การจองที่เชื่อมกัน เช่น OTA ต้นทาง + Walk-in Extension ต่อท้าย
Linked Stay Panel
แผงในระบบที่แสดงรายการ Segment ทั้งหมดของ Linked Stay
Linked Stay Badge
ป้ายเล็กๆ ใต้ชื่อแขกใน Reservations List แสดง Segment ที่เชื่อมกัน
Segment
ช่วงการพักหนึ่งๆ ในการจองที่ต่อเนื่องกัน เช่น OTA segment / Walk-in segment
Blocker
การจองอื่นที่ขวางทาง Extend Stay ในห้องเดิม — ต้องจัดการก่อน Commit
Swap Candidate
ห้องอื่นที่สามารถรองรับ Blocker ได้ เพื่อให้ OTA อยู่ต่อในห้องเดิม
OTA Extend Stay Orchestrator
Modal ในระบบสำหรับจัดการ Extend Stay ของ OTA — รองรับทั้ง Same Room และ Different Room
Preview / Precheck
การตรวจสอบล่วงหน้าก่อน Commit — ระบบแสดง Warning และตรวจ Blocker
Commit
การยืนยันและบันทึก Plan เข้าระบบจริง — ย้อนกลับยากหลังจากนี้
Strategy: Same Room
กลยุทธ์ Extend ที่ต้องการอยู่ในห้องเดิม
Strategy: Different Room
กลยุทธ์ Extend ที่ต้องการย้ายไปห้องอื่นหรือ Type อื่น
Option A: Keep OTA as-is
ย้ายห้อง OTA ทันที โดยไม่แตะวันจอง OTA เดิม
Option B: Shorten OTA first
ย่อวัน OTA ก่อน แล้วสร้าง Walk-in segment สำหรับช่วงที่ย้าย
OTA Platform Update
การอัปเดตวันใน Booking.com / Agoda ด้วยตัวเอง — ระบบไม่ทำให้อัตโนมัติ
Room Move History
ประวัติการย้ายห้องทั้งหมดที่บันทึกในระบบ สำหรับแต่ละ Reservation
Move Mode: Plan Move
กำหนดวันย้ายล่วงหน้า ระบบจะ execute อัตโนมัติเมื่อถึงวันนั้น
Override
การข้ามข้อจำกัด (เช่น Assigned Lock) โดยใส่หมายเหตุยืนยัน
Collect Method
วิธีรับชำระเงิน: Cash (เงินสด) / Transfer (โอน) / Card (บัตร)
Settlement Preview
การดูตัวเลขสรุปก่อนดำเนินการทางการเงิน เช่น Shorten, Check-out
HK (Housekeeping)
แผนกแม่บ้าน — ต้องแจ้งเมื่อมีการย้ายห้อง เพื่อทำความสะอาดห้องเก่า
